# Default report structure — 코드·실험 기반 6관점 리뷰

보고서는 사용자가 바로 의사결정할 수 있도록 아래 형태를 기본으로 한다. 표가 너무 많으면 하나로 합치고, 장문의 형식보다 **근거와 결정의 정확성**을 우선한다.

## [연구/저장소] 6관점 교차검토

**기준:** 현재 HEAD / 이전 검토 HEAD / 관련 이슈 / 증적·분석 도구 접근 가능 범위.

**핵심 결론 (2~4문장):** 무엇은 완료/검증, 무엇은 구현됐으나 미실증, 무엇은 설계/오라클 오류인지. 가장 큰 결함/정보가치와 조치 우선순위. 각 결론에 결론 범위(`target-proven / lab-proven / hypothesis-only`)를 붙인다.

### 1. 변경 요약 (커밋 검토 시)

| 확인한 변경 | 검증 수준 | 결론 범위 | 실제 실험 결과 | 남은 공백 |
| --- | --- | --- | --- | --- |
| 코드 경로 수정 | CODE_VERIFIED | lab-proven | NOT_TESTED | 새 독립 replay 필요 |

### 2. 여섯 관점의 독립 판정

| 관점 | 직접 확인한 근거 | 숨은 전제 / 실패 위험 | 판별 실험 | 판정 |
| --- | --- | --- | --- | --- |
| 실험과학 | ... | ... | ... | P0 ... |
| 런타임/도메인 | ... | ... | ... | P0 ... |
| 수학·제어이론 | ... | ... | ... | P1 ... |
| 취약점·퍼징 | ... | ... | ... | ... |
| 통계·인과추론 | ... | ... | ... | ... |
| 발견 에이전트 | ... | ... | ... | ... |

### 3. 가장 중요한 교차 모순 / 새 가설

최소 한 개 이상에 대해 `가설 / 코드 또는 증적 근거 / 대립 설명 / 재현 가능한 반증 실험 / 예상 관측 / 통과·실패시 다음 조치`를 설명한다.

### 4. 유효성 게이트

| Gate | 상태 | 근거/결측과 영향 |
| --- | --- | --- |
| G1 replay | PASS/FAIL/NOT_TESTED | ... |
| G2 observation | ... | ... |
| G3 oracle | ... | ... |
| G4 algorithm/treatment | ... | ... |
| G5 replication/causality | ... | ... |
| G6 knowledge update | ... | ... |

### 5. 권장 개발 순서

P0 → P1 → P2 작업을 실제 파일/테스트/책임 이슈와 연결한다. **연구 방향 Research Go**와 **현 스케줄러의 성능 승인 No-Go**가 동시에 성립할 수 있음을 명확히 적는다.

### 6. 범위·출처·이슈 변경

직접 재실행했는지, 코드만 읽었는지, 논문 수치가 해당 프로젝트에 적용 가능한지, GitHub 이슈를 실제 변경했는지 밝힌다. 사용자가 요청했다면 변경한 실제 URL을 포함한다.
